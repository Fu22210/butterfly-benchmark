# Разметка основного набора бабочек

- `gallery.html` показывает 400 фото с рамками. В карточке можно переключиться на оригинал.
- `annotations.jsonl` содержит по одной записи на фото в формате задания. Поля `left`, `top`, `width`, `height` нормализованы по оригиналу с учётом EXIF-ориентации. `boxes: []` означает отсутствие объекта в текущей версии разметки. Ошибки загрузки хранятся отдельно в `error`.
- `review_status.jsonl` хранит способ разметки каждого фото. `practice_reference` — пример, размеченный по изображению для тренировки. `visually_corrected` — черновик исправлен по изображению. `model_draft` — вывод модели, требующий ревью.
- `previews/` содержит JPEG-копии с рамками до 1120 пикселей по длинной стороне. `python butterfly_bbox/render_overlays.py` пересобирает копии и миниатюры из координат и соседней папки с оригиналами. Для скрипта нужен Pillow.
- `practice.html` — локальная тренировка на тех же 14 примерах, которые экспортированы для Яндекс Заданий.

Первый проход выполнен локальной Florence-2-base-ft. В тренировочные эталоны вошли 9 кадров с бабочками и 5 без них. Сверка по изображениям и автоматический черновик сделаны с помощью Codex. Для итогового golden set и отчёта по заданию ещё нужна независимая человеческая проверка. Особенно внимательно проверьте тонкие усики и лапки, перекрытия, мелкие объекты и пустые кадры. [Карточка использованной модели](https://huggingface.co/microsoft/Florence-2-base-ft)

## Подключение к Яндекс Заданиям

**Тренировка.** Создайте отдельный проект в редакторе HTML/CSS/JS. Подключите `toloka-handlebars-templates.js`. Вставьте `yandex/training.html`, `yandex/training.css` и `yandex/training.js` в соответствующие блоки. Спецификации входов и выходов лежат в `task_spec` файла `yandex/training.project.json`. Этот же файл можно использовать как тело запроса создания проекта. В тренировочный пул импортируйте `yandex/training_tasks.tsv`. Можно начать с одного примера в предпросмотре и проверить отправку до открытия пула. Файлы подготовлены по документации. В аккаунт Яндекс Заданий их не загружали. [Создание проекта через API](https://yandex.ru/dev/tasks-api/doc/ru/reference/projects/post-projects) · [Формат TSV и обучающих заданий](https://yandex.ru/support/tasks-requester/ru/guide/pool-csv)

Тренировка использует свой редактор прямоугольников. Штатный `image-annotation.js` удобен для основного проекта, но документация Яндекса отдельно предупреждает об ограничении обучения и контроля в проектах, где подключён этот редактор. `training.js` проверяет геометрию и записывает результат в `passed`. Платформа сравнивает булево поле с `GOLDEN:passed`. Координаты ответов по-прежнему сохраняются в `result`. Поскольку эталон передаётся в браузер, этот режим годится для практики с подсказками. Для зачётного экзамена скрытые эталоны следует держать у заказчика и проверять выгруженные ответы тем же `grade.js`. [Штатный редактор](https://www.yandex.ru/support/tasks-requester/ru/guide/t-components/image-annotation) · [API класса Task](https://yandex.ru/support/tasks-requester/ru/guide/js/task)

**Сбор основной разметки.** Файлы `yandex/production.project.json` и `yandex/production_tasks.tsv` задают проект со штатным редактором и 400 входных заданий. Эталонных координат во входных заданиях нет. В выходах есть `result` и отдельный `status` со значениями `boxes`, `none` и `load_error`. Тренировочные 14 ID уже входят в эти 400, поэтому если один исполнитель проходит обе стадии, перед выдачей уберите из его рабочего пула уже показанные ему карточки или назначьте их другим исполнителям.

## Как проверяются рамки

Видимая взрослая дневная или ночная бабочка получает одну рамку. В неё входят видимые крылья, тело, усики и лапки. Окклюзия и границы фотографии ограничивают рамку видимой частью объекта. Для нескольких бабочек нужны отдельные прямоугольники, даже если рамки пересекаются. Гусеницы, куколки, другие насекомые и тени остаются без рамок. Если исходный снимок недоступен, выбирается ошибка загрузки.

Для каждого эталона JavaScript ищет отдельную рамку исполнителя. По умолчанию требуется IoU от 0,50, покрытие эталона от 85% и доля пересечения в рамке исполнителя от 55%. Три условия вместе допускают небольшой сдвиг или запас, отсекают сильную обрезку и рамки с большим лишним фоном. Значения можно изменить в `BBOX_POLICY`. Правила годятся для тренировочных оценок, метрика проекта считается отдельно по условию задания.

`grade.js` принимает как `left/top/width/height`, так и формат Яндекса `rectangle → data → p1, p2`. Для анализа выгрузки `gradeAnswer(status, result, reference)` возвращает `ok`, `code` и сообщение с подсказкой.
